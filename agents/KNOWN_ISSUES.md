# Known issues and validation ledger

This concise living ledger complements the detailed limitations in [`../docs/SOFTWARE_DESIGN.md`](../docs/SOFTWARE_DESIGN.md). Change status only when evidence supports it.

| ID | Status | Area | Issue and evidence | Next action |
|---|---|---|---|---|
| DEV-01 | RESOLVED | Windows source tracking | An unanchored root `models/` ignore rule excluded the C# `Models/` source folder on Windows. The first GitHub Actions build caught the missing files; root-anchored ignore rules and a passing hosted build fixed it in commit `4fb740e`. | Keep root artifact ignore patterns anchored and verify new files appear in `git status`. |
| UI-03 | AUTOMATED / MANUAL CHECK OPEN | Startup lifecycle | Named-mutex/event tests cover one primary, secondary activation signaling, and ownership release; repeated-launch smoke confirms the secondary process exits while the primary remains. Visible foreground activation, tray exit, and global-hotkey conflict behavior still need manual Windows validation. | Check visible launch-twice activation, tray exit, and shortcut conflict on Windows without using Notion content. |
| UI-01 | OPEN | Notion integration | Clipboard formats and foreground-window flow have not been verified against a real Notion page. | Keep integration claims explicitly unverified; consider a non-destructive isolated-editor harness before real-page automation. |
| CORE-01 | PARTIALLY MITIGATED | Selection safety | Fake-environment tests cover captured window/process identity and foreground checks around simulated copy/paste; capture also rejects clipboard-sequence changes during the text read. These checks cannot detect selection/caret changes inside the same window/process or make OS input atomic. | Keep the explicit warning and source preview; investigate accessible ways to confirm selection continuity without private Notion APIs. |
| CORE-02 | OPEN | Clipboard | Capture and Apply replace previous clipboard data; arbitrary clipboard formats are not preserved. Capture detects a clipboard update during its text read but does not restore the prior contents. | Design a preservation policy and automate supported-format coverage before implementing restoration. |
| PERF-01 | OPEN | Model quality/latency | After a structure-prompt refinement and benchmark-input clarification, one run scored qwen2.5:7b 5/8 (2/2 proofreading, 3/6 structure; 4.1s mean) and qwen2.5:3b 4/8 (1/2 proofreading, 3/6 structure; 4.5s mean for completed requests). One 3B request failed when Ollama's llama-server terminated during CUDA initialization. 7B still missed labeled-update/table/quote checks; 3B missed labeled-update/quote/shell-command checks. Results are one synthetic run, not directly comparable with previous cases or runs. | Repeat the run, diagnose the 3B runtime failure, and compare with user-approved examples before considering a default change. |
| UI-02 | PARTIALLY MITIGATED | Preview | The formatted preview uses allow-listed WPF elements and a side-by-side text comparison highlights word/punctuation edits. It is not WYSIWYG; the textual comparison does not show formatting-only edits or align moved blocks, and large diffs collapse to a whole-text replacement. | Keep the scope disclosure; assess whether a formatting/block-structure comparison is needed after usability feedback. |
| CORE-03 | OPEN | Model semantics | Schema checks cannot determine whether a valid suggestion changes meaning or misses an error. | Keep mandatory preview and add synthetic quality checks without treating them as proof of correctness. |

No known issue authorizes bypassing preview, local-only inference, or model-output validation.
